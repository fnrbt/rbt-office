Composition Patterns: Independent Components

Pattern 1: Grid Only (No Tabs)

Single-sheet application. The Spreadsheet component renders one sheet. No tabs, no workbook - just a standalone grid.

Use case: Embedded calculator, single-sheet editor, simple data entry

Note: This is just createSpreadsheet(container) - no workbook, no tabs.

Pattern 2: Tabs Below (Excel Style)

Classic Excel layout: grid on top, tabs on bottom. Components are completely separate. The Tabs component doesn't know about the grid, the grid doesn't know about tabs.

Use case: Multi-sheet workbook, Excel clone, data analysis tool

Pattern 3: Sidebar Navigation (Custom)

Tabs component replaced with custom sidebar. Same grid, different navigation. Apps can use Workbook model without the Tabs component.

Use case: Custom dashboard, report builder, data management UI

Architecture Summary

Three Independent Layers:
  • Workbook.fs - Pure data model (sheets, tables, references)
  • Spreadsheet.fs - Grid renderer (takes SpreadsheetModel, no workbook knowledge)
  • Tabs.fs - Optional UI component (can use, replace, or omit)
Apps Compose:
  • Pattern 1: Spreadsheet only (no workbook, no tabs)
  • Pattern 2: Workbook + Spreadsheet + Tabs (Excel clone)
  • Pattern 3: Workbook + Spreadsheet + custom nav (sidebar)
  • Pattern 4: Workbook + Spreadsheet + custom nav (dropdown)
Key Principle:

The grid doesn't know about tabs. The tabs don't know about the grid. The workbook is just data. Apps wire components together however they want.
